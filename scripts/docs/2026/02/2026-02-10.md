# 네트워크 기본 ( 02 )

## 개요

네트워크의 기본 개념은 모든 IT 인프라의 중추를 형성합니다. 특히 서브넷팅과 라우팅은 네트워크 설계와 관리의 핵심 요소로, 효율적인 네트워크 자원 관리와 안정적인 데이터 전송을 보장합니다. 서브넷팅은 네트워크를 더 작은 서브넷으로 나누어 주소 공간을 최적화하고, 라우팅은 이러한 서브넷 간의 데이터 전송 경로를 결정합니다. 이 과정에서 패킷 전송의 효율성과 네트워크 보안이 향상됩니다. 실무에서는 이러한 개념이 대규모 네트워크 환경에서 트래픽을 관리하고, 비용을 절감하며, 네트워크 확장성을 고려하는 데 필수적입니다.

## 상세 내용

### 서브넷팅

**정의와 동작 원리**
서브넷팅은 하나의 네트워크를 더 작은 서브넷으로 나누는 과정입니다. 각 서브넷은 고유한 네트워크 주소와 서브넷 마스크를 가집니다. 서브넷 마스크는 IP 주소의 네트워크 부분과 호스트 부분을 구분하는 데 사용됩니다.

**왜 이렇게 설계되었는지**
서브넷팅은 IP 주소 공간을 효율적으로 사용하기 위해 설계되었습니다. 초기 IP 주소 체계에서는 많은 주소가 낭비되었고, 서브넷팅을 통해 이를 해결했습니다. 이는 특히 IPv4에서 중요한데, 주소 공간이 제한적이기 때문입니다.

**실무 시나리오**
회사의 본사와 지사가 여러 위치에 있을 때, 각 지사에 서브넷을 할당하여 독립적으로 네트워크를 관리할 수 있습니다. 이는 네트워크 트래픽을 줄이고, 보안을 강화하며, 유지보수를 용이하게 합니다.

**주의사항**
서브넷팅 시 호스트 수를 정확히 계산해야 하며, 서브넷 마스크를 잘못 설정하면 네트워크가 비효율적으로 운영될 수 있습니다.

### 패킷트레이서

**정의와 동작 원리**
패킷트레이서는 Cisco 네트워크 장비의 동작을 시뮬레이션하는 도구입니다. 이는 네트워크 토폴로지를 설계하고, 다양한 시나리오를 테스트하며, 네트워크 구성의 문제를 파악하는 데 사용됩니다.

**왜 이렇게 설계되었는지**
실제 하드웨어 없이도 네트워크를 설계하고 테스트할 수 있도록 개발되었습니다. 이는 비용 절감과 학습 곡선 완화를 위해서입니다.

**실무 시나리오**
네트워크 변경을 계획할 때 패킷트레이서를 통해 변경의 영향을 미리 검증할 수 있습니다. 이는 비즈니스 운영에 미치는 영향을 최소화할 수 있습니다.

**주의사항**
시뮬레이션 결과는 실제 환경과 차이가 있을 수 있으므로, 배포 전에 항상 실제 환경에서 테스트가 필요합니다.

### ARP (Address Resolution Protocol)

**정의와 동작 원리**
ARP는 IP 주소를 MAC 주소로 변환하는 프로토콜입니다. 네트워크 상에서 장치 간 통신 시 IP 주소만으로는 데이터 링크 계층에서 통신이 불가능하기 때문에 MAC 주소로의 변환이 필요합니다.

**왜 이렇게 설계되었는지**
이더넷 네트워크에서 IP 주소만으로는 장치 식별이 불가능하여, 물리적 네트워크 계층에서 통신하기 위해 MAC 주소로 변환하는 방식을 채택했습니다.

**실무 시나리오**
애플리케이션 서버가 데이터베이스 서버에 접근할 때, 서버의 IP 주소를 MAC 주소로 변환하여 정확한 데이터 전송이 이루어지도록 합니다.

**주의사항**
ARP 스푸핑과 같은 보안 취약점에 주의해야 하며, 네트워크 보안을 강화하는 메커니즘이 필요합니다.

### Default Gateway

**정의와 동작 원리**
Default Gateway는 네트워크 외부로 데이터를 전송할 때 경유하는 경로입니다. 이는 주로 라우터의 IP 주소로 구성됩니다.

**왜 이렇게 설계되었는지**
네트워크 내의 호스트 간 통신은 라우터를 통해 이루어지며, 외부 네트워크로의 데이터 전송을 위해 경유지로서 역할을 수행합니다.

**실무 시나리오**
내부 네트워크에서 인터넷으로 접속할 때, 모든 트래픽이 라우터를 통해 전송되어야 하는 경우에 사용됩니다.

**주의사항**
Default Gateway가 잘못 설정되면 외부와의 통신이 불가능해질 수 있으므로 정확한 설정이 필요합니다.

### 라우팅 (Routing)

**정의와 동작 원리**
라우팅은 데이터 패킷의 전송 경로를 결정하는 과정입니다. 이는 정적 또는 동적 라우팅 방법을 통해 이루어집니다.

**왜 이렇게 설계되었는지**
효율적인 데이터 전송과 네트워크 확장을 위해 다양한 경로를 선택하여 데이터 손실을 최소화하고 대역폭을 최적화합니다.

**실무 시나리오**
복잡한 네트워크 환경에서 여러 경로 중 최적 경로를 선택하여 트래픽을 관리하고, 장애 발생 시 대체 경로로 전환합니다.

**주의사항**
라우팅 테이블이 정확하지 않으면 패킷이 잘못된 경로로 전달되어 네트워크 효율이 저하될 수 있습니다.

## 코드 예제

### 서브넷팅 예제

```bash
# 네트워크 주소: 192.168.1.0/24
# 서브넷 마스크: 255.255.255.0

# 서브넷팅 후 /26으로 서브넷팅
# 새 서브넷 마스크: 255.255.255.192

# 네트워크 범위 계산
192.168.1.0    # 첫 번째 서브넷
192.168.1.64   # 두 번째 서브넷
192.168.1.128  # 세 번째 서브넷
192.168.1.192  # 네 번째 서브넷
```

### 정적 라우팅 설정 예제

```bash
# 라우터 R1에 정적 라우트 설정
[R1#]
conf t
ip route 10.10.2.0 255.255.255.0 192.168.1.2
# 10.10.2.0 네트워크로 가는 경로 설정, Next-hop: 192.168.1.2
```

## 핵심 포인트

1. **서브넷팅은 네트워크 주소의 효율적 사용을 위한 필수 기술이다.**
   - IP 주소의 낭비를 최소화하고 네트워크 관리 비용을 절감합니다.

2. **패킷트레이서는 네트워크 설계와 테스트의 강력한 도구이다.**
   - 실 환경에서의 위험을 줄이고, 비용을 절감합니다.

3. **ARP는 네트워크 계층 간 주소 변환을 담당한다.**
   - IP 주소를 MAC 주소로 변환하여 데이터 링크 계층의 통신을 가능하게 합니다.

4. **Default Gateway는 외부 네트워크와의 연결을 위한 필수 경로이다.**
   - 외부와의 통신이 필요할 때 주로 사용됩니다.

5. **라우팅은 네트워크 효율성과 확장성을 보장한다.**
   - 다양한 경로 선택과 장애 복구를 지원합니다.

## 면접 대비 질문

1. **서브넷팅이란 무엇이며, 왜 필요한가요?**
   - 서브넷팅은 네트워크를 더 작은 서브넷으로 나누는 과정입니다. 이는 IP 주소 공간을 효율적으로 사용하고 네트워크 트래픽을 관리하기 위해 필요합니다.

2. **패킷트레이서와 실제 환경의 차이점은 무엇인가요?**
   - 패킷트레이서는 시뮬레이션 도구로, 실제 환경과 차이가 있을 수 있습니다. 따라서 배포 전 실제 환경에서의 테스트가 필요합니다.

3. **ARP의 역할은 무엇이며, 보안 취약점은 무엇인가요?**
   - ARP는 IP 주소를 MAC 주소로 변환합니다. ARP 스푸핑 공격의 위험이 있으며, 이를 방지하기 위한 보안 조치가 필요합니다.

4. **Default Gateway는 어떤 역할을 하나요?**
   - Default Gateway는 네트워크 외부로의 데이터 전송 경로를 제공합니다. 이는 네트워크 외부와의 연결을 가능하게 합니다.

5. **정적 라우팅과 동적 라우팅의 차이점은 무엇인가요?**
   - 정적 라우팅은 수동으로 경로를 설정하며, 고정적입니다. 동적 라우팅은 프로토콜에 의해 자동으로 경로를 설정하며, 변화에 적응할 수 있습니다.
